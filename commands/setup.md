You are installing the Backbrief Kit from this plugin's bundled payload into the user's environment, then configuring it. Plain language throughout; the user may be non-technical.

1. **Locate the payload.** This command ships inside the backbrief-kit plugin. Find the plugin's install directory: search `~/.claude/plugins/` for a directory that contains `kit-payload/team/agents/orchestrator.md` (glob for that path). Call it PLUGIN_ROOT. If you cannot find it, say so and stop — do not improvise a download. Read `PLUGIN_ROOT/kit-payload/team/VERSION` and say which version you are installing, first.
2. **Ask one question:** "Install the team globally (available in every project on this machine) or just in this project? Most people choose globally." Default to globally if the user is unsure.
3. **Install the team.** Copy the CONTENTS of `PLUGIN_ROOT/kit-payload/team/` into `~/.claude/` (global) or `<project>/.claude/` (per-project). Create the target if needed. Guard against nesting mistakes: the result must be `.claude/agents/...`, not `.claude/team/...` or `.claude/.claude/...`.

   Overwrite-or-skip depends on whose file it is:
   - If the destination's `.claude/VERSION` names this product at an OLDER version (or the destination's `.claude/CLAUDE.md` opens with our `# Backbrief Kit` heading (or the older `# Shiproom Kit` / `# Agent OS Kit` one) from before version stamping), this is an update of our own earlier install: say what they are moving from and to, back up `.claude/memory/` to `<project>/_backbrief-backups/<old-version>-<date>-<time>/` (bare version number, colon-free time) first, then OVERWRITE the files the kit ships — skipping them would leave a stale mix and report success anyway. Never touch `.claude/memory/` itself or anything the user wrote.
   - If the destination's `.claude/VERSION` is NEWER than the payload, stop and say so; do not go backwards without an explicit request to roll back.
   - If existing files are NOT ours (no stamp, no kit heading), never overwrite: skip each collision and note it.
4. **Install the scaffold.** Copy the CONTENTS of `PLUGIN_ROOT/kit-payload/scaffold/` into the current project root, never overwriting existing files. This adds `context/` (including `context/reference/` with the `SOURCES.md` knowledgebase index), `inputs/`, `outputs/`, `workflows/`, a project `CLAUDE.md` template, and a hidden `.claude/memory/` (decision log + preferences templates) — copy dotfolders too, or the memory files silently go missing.
5. **Verify.** Check and report a one-line pass/fail each: 12 agent files; commands including critique, council, grade-idea, handoff, next, resume, setup, verify-install; 10 rules; 4 skills with SKILL.md each; scaffold folders present including `context/reference/SOURCES.md`; `.claude/VERSION` reads the version you installed; no nested `.claude/.claude/`. If anything failed, fix it (with the user's yes) before continuing.
6. **Interview.** Ask, one at a time: what the project is (a sentence or two); what they want done in the next few weeks; any personal "never without asking" rules beyond the standard stops; anything already decided; whether they have a knowledgebase the team should work from — documents they own (digital books, guides, product docs, standards) AND links (a docs site, a Notion page, an online guide) — filing documents into `context/reference/` and recording every source as a row in `context/reference/SOURCES.md` with a note on when to use it; and how much they want the team to drive (walk-me-through = `guided`, recommended; just-tell-me = `manual`; do-early-steps = `auto-prep`) — write that to `.claude/memory/preferences.md`. Write the other answers into `context/strategy/current-state.md`, `context/strategy/current-priorities.md`, and (for prior decisions) `.claude/memory/decisions.md`, in the user's own words. Read the two strategy files back in under 100 words and correct anything they flag.
7. **Close with exactly:** "Setup is done. State a goal in plain words and the team will plan it, build it, and verify it. If you are ever unsure what to do, type /next and I will tell you where you stand. Also useful: /critique to stress-test an idea, /council for a five-advisor debate, /handoff to end a session, /resume to start the next one. To update the kit later: /plugin update, then run this setup again — it upgrades the kit's own files, adds what's new, and never touches yours."
8. **Then one last line, optional and said once:** a plugin install never asks for an email, so the kit has no way to tell them when a new version ships. If they want an email when a meaningful update ships, the form at https://backbrief.ai/get-the-kit?utm_source=plugin&utm_medium=setup-invite is the update list. One sentence in your own words, take no for an answer, and never raise it again.

Notes: after step 3 the kit's own commands (unprefixed /next, /critique, /setup, /verify-install, etc.) are installed at the user level or project level — tell the user to use those, not the /backbrief-kit: prefixed ones, from now on. If a file skip happened because the user already had a same-named file of their own, list the skips and point to INTEGRATION guidance in the kit README rather than resolving silently.
